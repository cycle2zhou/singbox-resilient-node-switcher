## Context

项目是面向 GUI.for.SingBox 的独立插件，不改 GUI 核心，不改用户现有插件。当前实际配置中，主组 `🚀 节点选择` 是 `selector`，包含大量成员，其中直接成员 `🎈 自动选择` 是 `urltest`，其余主要是节点出站。sing-box Clash API 提供 `/proxies`、`/proxies/{name}/delay` 和 `PUT /proxies/{selector}`。

运行跟踪显示，sing-box `/delay` 使用 HEAD 且不读取响应体，可能显著低估用户实际访问延迟；真实业务访问通过 GFS 的 native `Plugins.HttpGet` 走系统代理，更接近用户感知，但请求成本更高，且底层请求无法被 JavaScript 的软超时真正取消。当前监控把 HEAD、真实 GET、判定和切换放在同一个 `watchCycle` 中，真实探测期间会使后续轮次因 `watchInProgress` 被跳过；盯梢退出也主要依据 HEAD 成功，不能充分证明新节点真实可用。

本次设计是在既有可恢复 Selector 监控基础上的增量架构调整。目标是让“手动切换到正常节点不误切换、切到高延迟或真实不可用节点时快速接管”，同时控制 GFS WebView/native 请求负载。既有手动切换的 `stableKey` 识别修复必须保留。

## Goals / Non-Goals

**Goals:**

- SHALL 将 HEAD 主动探测作为低成本、快速的连通性/延迟信号，而不把它当作真实业务可用性的唯一证明。
- SHALL 在盯梢期对高延迟、探测失败和真实 GET 失败采用快速切换策略；盯梢期高延迟不再等待普通状态的两次阈值。
- SHALL 只有真实 GET 成功且延迟达标后，才累计盯梢稳定次数并允许退出盯梢期。
- SHALL 让 HEAD 监控周期不被单个真实 GET 阻塞；真实探测必须单飞、有界，并丢弃对应节点已经变化后的过期结果。
- SHALL 保留候选节点的 HEAD 复核、切换后真实验证、失败候选冷却和继续尝试机制。
- SHALL 通过 URL 轮换、请求单飞和不同状态下的间隔控制性能；任何时刻真实 GET 任务不得超过一个。
- SHALL 提供可观察的真实探测开始、结果、判定和切换事件，便于区分未检测、检测中、轮次跳过和驻留期拦截。

**Non-Goals:**

- 不改变主 Selector、URLTest、provider healthcheck、节点配置或订阅内容的所有权边界。
- 不保证主动探测覆盖所有业务网站，不把真实探测成功表述为所有业务完全恢复。
- 不通过提高全局并发或无限缩短间隔来解决延迟问题。
- 不实现无法取消的 native HTTP 请求的强制中断；只保证其过期结果不会污染当前节点状态。
- 不在本次改造中引入第三方依赖或拆分现有单文件插件构建机制。

## Decisions

### D1：采用分层检测信号

- **选择**：保留 `/delay` 作为每轮快速 HEAD 检查；将 GFS native `HttpGet` 作为真实 GET 信号，用于盯梢稳定性和“HEAD 通但实际慢/失败”的关键判定。
- **理由**：HEAD 成本低且适合快速发现明显故障，但已证实会低估真实 GET；真实 GET 更准确但成本更高，不能用来替代所有 HEAD 轮次。
- **已考虑 alternative**：只使用 HEAD；被拒绝，因为无法覆盖 HEAD 快但真实访问慢。每轮并行访问所有真实 URL；被拒绝，因为会放大 native 请求负载且多个 URL同时失败时会阻塞判定。

### D2：盯梢稳定性必须由真实 GET 证明

- **选择**：手动或插件切换后保持 `stalking=true`；真实 GET 成功且延迟不超过 `realDelayMs` 才增加稳定计数；连续 `realStalkSuccessThreshold` 次达标后退出盯梢。盯梢期间 HEAD 高延迟一次即允许触发切换，失败和真实 GET 超时/超阈值也立即触发。
- **理由**：HEAD 成功不能证明用户访问正常；手动切换后的首要目标是快速确认新节点是否真的可用。
- **已考虑 alternative**：连续两次 HEAD 成功退出；被拒绝，因为会把“HEAD 快、真实 GET 慢”的节点误判为稳定。盯梢期间所有成功都立即退出；被拒绝，因为单次成功不能抵抗网络波动。

### D3：HEAD 监控与真实 GET 解耦

- **选择**：HEAD `watchCycle` 继续按监控间隔运行；真实 GET 作为独立单飞任务调度。同一节点已有真实任务时不重复发起，结果携带节点稳定身份和 generation；返回时若当前 Selector 已变化或 generation 已失效，则丢弃结果。真实任务未完成时不阻塞新的 HEAD 监控和状态同步。
- **理由**：GFS native 请求的软超时不能取消底层请求；将其放在同一锁内会使后续轮次跳过，造成状态滞后和切换延迟。单飞加过期结果丢弃既控制资源，又避免旧结果误伤新节点。
- **已考虑 alternative**：继续把真实 GET `await` 放在 `watchCycle`；被拒绝，因为慢请求会使 `watchInProgress` 长时间为真。无限并行真实 GET；被拒绝，因为底层请求不可取消，会快速耗尽连接和线程资源。

### D4：真实 GET 默认轮换单 URL，关键场景再补测

- **选择**：正常状态按可配置间隔（默认 `realProbeIntervalMs=15000`）轮换一个真实 URL；盯梢状态按较短间隔轮换一个 URL；真实失败或切换后首次验证可按既有候选策略补测其他 URL。真实任务全局并发上限为 1。
- **理由**：单 URL 已足以形成低成本趋势信号，轮换可以降低某一站点自身故障导致的误判；关键故障路径仍保留多 URL 交叉确认能力。
- **已考虑 alternative**：每轮并行全部 URL；被拒绝，因为正常运行成本高且会受最慢 URL拖累。只固定一个 URL；被拒绝，因为会产生探测目标盲区。

### D5：区分盯梢期与正常期阈值和频率

- **选择**：正常期保留较稳健的 `failureThreshold`、`slowThreshold` 和最短驻留；盯梢期使用一次失败/一次高 HEAD 延迟/一次真实失败或超阈值即可进入切换流程，并使用更短真实请求超时。盯梢只由真实 GET 达标计数退出。
- **理由**：正常期需要抵抗瞬时抖动；手动或刚切换的节点已经是高风险状态，继续等待普通阈值会造成用户可感知断网窗口。
- **已考虑 alternative**：全状态统一把阈值调为 1；被拒绝，因为会放大正常运行期的误切换和震荡。全状态统一缩短探测间隔；被拒绝，因为性能成本持续存在且不能解决错误信号来源。

### D6：以事件时间线支持验证和诊断

- **选择**：在内存中维护最近 N 条（默认 50）事件环形队列，记录 watch、real probe、decision、switch 事件，至少包含事件时间、stableKey、结果、耗时、是否过期/跳过和切换原因；详细事件仅保存在内存，`state.json` 只保留聚合计数与最近摘要，不持久化逐条事件。
- **理由**：仅凭 `realSlowCount`、`stalking` 或 30 秒一次的状态文件无法区分检测中、轮次跳过、驻留期阻塞和外部切换竞态。
- **已考虑 alternative**：仅依赖现有聚合计数；被拒绝，因为无法复盘用户报告的具体时间线。每轮写文件；被拒绝，因为会增加 GFS data I/O 和状态文件竞争。

## Risks / Trade-offs

- [Risk] native 请求在软超时后仍会继续运行 → Mitigation: 全局真实任务单飞、结果 generation 校验、旧结果丢弃；不把取消语义伪装成已取消。
- [Risk] 真实 GET 单 URL 可能遇到单站点自身异常 → Mitigation: URL 轮换；真实失败或切换后验证失败时按关键路径补测其他 URL。
- [Risk] 盯梢期一次高延迟可能因瞬时抖动触发切换 → Mitigation: 只在手动/插件切换后的短期盯梢采用激进策略；正常期继续使用连续阈值，并保留冷却和候选复核。
- [Risk] HEAD 与真实 GET 结果时间不同步 → Mitigation: 每个真实结果绑定 stableKey 与 generation；当前节点变化后结果作废。
- [Risk] 真实探测仍不能证明所有业务可用 → Mitigation: UI、README 和状态事件明确标记为主动 GET 探测，不宣称全站点恢复。
- [Risk] 事件记录增加内存和持久化体积 → Mitigation: 只保留有限长度的最近事件环形队列，持久化仍按现有低频计时器执行。
- [Risk] 外部组件持续改写主 Selector → Mitigation: 每轮先读最新 `now`；检测到 stableKey 变化时重置窗口并进入盯梢；事件中记录外部变化与插件切换来源，避免将外部行为归因于插件。

## Migration Plan

1. 先在 `test/monitor.test.js` 为盯梢高延迟一次切换、真实 GET 才能退出盯梢、真实探测单飞、过期结果丢弃和事件记录编写失败测试。
2. 在 `src/config.js` 增加真实探测正常期/盯梢期调度和真实盯梢稳定阈值的归一化默认值；默认参数以测试和实际 GFS 负载验证结果为准，不直接提高并发。
3. 在 `src/monitor.js` 实施解耦调度，保留现有 `stableKey`、候选 HEAD 复核、PUT 后 `now` 确认和切换后真实验证。
4. 同步 `scripts/plugin-adapter.js`、`plugins/gfs.json`、构建产物和 `README.md`，明确配置含义和主动探测限制。
5. 运行单测、全量测试、构建、语法检查，并在 GFS 中验证三条路径：正常 Linux 节点不切换；高 HEAD 延迟节点快速切换；HEAD 正常但真实 GET 慢/失败节点快速切换。
6. 部署前备份用户插件；若出现误切换或负载异常，停止插件并恢复备份文件。插件不改 sing-box 配置、不删节点，回滚无需恢复配置。
